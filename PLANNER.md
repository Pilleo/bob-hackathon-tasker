# Planner starter

This is the portable planner portion of Agent DevKit. It builds without the ADK application or an installed ADK wrapper. The `EXPORT-MANIFEST.txt` records the source revision and exact exported file hashes. See `ARCHITECTURE.md` for boundaries and extension points.

Requires a JDK 25 Gradle toolchain; emitted bytecode targets Java 21. Run `./gradlew check :planner-app:installDist` to test every module and build the CLI. From `examples/name-validation`, run `../../planner-app/build/install/planner-app/bin/planner-app issue new --title "Reject blank names" --target src/main/kotlin/sample/Main.kt` (repeat `--target` for each file). `target_files` is mandatory frontmatter used for scheduling file conflicts. Edit the resulting Markdown Context when ready; agent-generated steps do not declare separate file claims. `schedule --issues docs/internals/backlog/<issue>.md --capacity 2` proposes a batch immediately, without requiring review, but does not execute or authorize work. `examples/description.md` shows a sample request. Place IBM Bob task-session screenshots in `bob_sessions/` and commit them with your submission; that directory is intentionally not ignored.

For a live ACP agent, run `./gradlew :planner-app:run --args='planner setup --name my-agent --agent /absolute/path/to/acp-server'`, then `issue elaborate <path>` and `review-issue <path>`. Add repeated `--arg <value>` flags if the ACP executable needs startup arguments, such as `--arg --stdio`. Live ACP requires a working Linux bubblewrap sandbox and the agent's own authentication. This ACP client does not provide agent-requested filesystem or terminal tools: agents that require those client capabilities fail explicitly rather than producing a review. Omitting `--model` avoids depending on optional model-selection support.

`planner-app` optionally uses installed ast-grep, Codanna and Git to search candidate declarations, verify exact named classes/functions, and inspect callers. Set up and index Codanna **in the project being planned** (`codanna index .`), then keep the index current. An issue elaboration may use a second ACP turn when verified source or an actionable target error can improve the first proposal. An unchanged generated section can be revised automatically; if a human edits that section, its in-file provenance marker prevents an overwrite. Answering a generated question is an explicitly supported human edit: the answer stays intact across corrections. Existing `decision` questions cannot be removed, renamed, reclassified, redirected to different steps, or answered by the agent; investigation results can be agent-supplied. Review findings in the managed review block do not change the ownership hash. The entire first proposal is included in refinement, with evidence separately bounded; generated proposals exceeding its budget fail explicitly. Repository-tool calls have a 45-second budget **per evidence pass** (agent time does not count), live output caps, and process-tree cleanup. `planning-context` and `review-issue` use the same evidence adapter. Missing tools or a missing Git revision produce explicit incomplete evidence. Without an agent, issue creation and deterministic tests still work; without verified evidence the issue remains an editable draft.

The export contains neither ADK runtime tooling nor local agent configuration. Never commit credentials or private configuration. The project that receives this starter owns its license and distribution decisions.
